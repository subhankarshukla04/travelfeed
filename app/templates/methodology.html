Methodology

travelfeed aggregates RSS feeds from a curated set of travel-tech, airline, and hospitality publications. Each article is filtered for travel relevance, tagged for section / region / theme, matched against a list of tracked travel companies, and scored for likely strategic relevance to a strategy reader.

Pipeline

  1. Ingest. RSS feeds polled every 4 hours. Real-browser User-Agent. Polite rate limits.
  2. Filter. Travel-relevance check rejects articles without travel keywords or tracked-company mentions.
  3. Tag. Heuristic regex pass first (free, instant). LLM tagger refines where needed.
  4. Match. Word-boundary regex against ~30 tracked travel companies and aliases.
  5. Score. Multi-factor formula — see below.

Score formula

score = source_tier_weight        (1–25)
      + theme_match               (0–25, capped)
      + region_boost              (0–15 — MENA/APAC weighted higher)
      + company_match             (0–15 — tracked travel co's)
      + capital_signal            (+10 if M&A / IPO / funding / commission topic)
      + recency_decay             (0–10, linear over 30 days)

Strict enum validation on tags — out-of-vocabulary section / region / theme values are dropped rather than displayed.

What it isn't

travelfeed is the input layer. It doesn't write summaries, generate commentary, or replicate editorial judgment. Articles link directly out to the original source. No analytics on this site. No login. No newsletter signup.
